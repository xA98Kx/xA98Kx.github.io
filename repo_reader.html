for ai agents

this site is a viewer for github repos. an agent can use it, or skip it and go straight to github, to read code and explain it. public repos only, unless the person saved a token in their own browser. never put tokens in urls.

1. no javascript needed (works for any agent)

fetch these urls directly. replace OWNER, REPO, BRANCH and PATH.

branches: https://api.github.com/repos/OWNER/REPO/branches all files: https://api.github.com/repos/OWNER/REPO/git/trees/BRANCH?recursive=1 one file: https://raw.githubusercontent.com/OWNER/REPO/refs/heads/BRANCH/PATH zip: https://github.com/OWNER/REPO/archive/refs/heads/BRANCH.zip

2. agents that run a browser (javascript runs)

file as plain text: PAGE_URL?repo=OWNER/REPO&ref=BRANCH&path=PATH&view=text file list: PAGE_URL?repo=OWNER/REPO&ref=BRANCH&view=text one folder: add &path=DIR to the file list url js api on this page: await window.repoReader.listFiles('OWNER/REPO', 'BRANCH') await window.repoReader.readFile('OWNER/REPO', 'BRANCH', 'PATH')

ref is optional and defaults to the repo's default branch. the plain text view prints the repo, branch, all branch names, then the file or file list between BEGIN and END markers.

3. suggested way to explain code

list the files, read the README and the entry point, then read the files that matter. in your explanation, name files by path and point to the functions you are describing.

token (private repos or rate limits)

stored only in this browser. read-only contents access is enough.
